## 공유 라이브러리를 검색할 디렉터리

- 프로그램이 공유 라이브러리에 의존하는 경우, 동적 링커가 해당 공유 라이브러리를 시스템에서 검색 

- main이 libfoo.so에 의존하고 있다는 정보 = main의 PT_DYNAMIC 세그먼트에 기록됨 

    - readelf --dynamic main 명령어를 사용해, PT_DYNAMIC 세그먼트의 내용을 읽어올 수 있음 

    - NEEDED로 표시된 부분 - 의존하는 라이브러리 정보 

    - 동적 링커는 이 정보를 기반으로 libfoo.so를 시스템에서 검색한 후 프로세스 메모리에 로드 

- PT_DYNAMIC 세그먼트에 기록된 문자열에 슬래시가 포함되어 있다면, 동적 링커는 이 문자열을 상대 경로 또는 절대 경로로 해석 

    - 그렇지 않다면, 지정된 디렉터리를 검색해 해당 파일을 찾음 

- main -> libfoo.so, libc.so.6 모두 슬래시를 포함하지 않으므로 동적 링커는 이 두 공유 라이브러리를 지정된 디렉터리에서 찾게 됨 

### 보안 실행 모드

- 동적 링커 실행 모드 중 하나 

- 실행 시 보조 벡터에 AT_SECURE 태그를 가진 항목이 포함되어 있는 경우, 동적 링커는 보안 실행 모드로 동작함 

- 보안 실행 모드에선 동적 링커의 일부 환경 변수 동작이 변경됨 

    - LD_LIBRARY_PATH를 무시 등 

- 보조 벡터에 AT_SECURE 태그를 가진 항목이 포함되고, 동적 링커가 보안 실행 모드로 실행되는 경우는 여러 상황에서 발생 가능 

    - 대표 예: 프로세스의 실효 유저 ID와 실제 유저 ID가 다른 경우 

    - 프로그램 파일에 setuid 속성이 부여되어 있어 프로그램 파일의 소유권 권한으로 프로그램이 실행되어 있다고 지정?

        - case = 동적 링커가 LD_LIBRARY_PATH를 읽고 그 디렉터리에서 공유 라이브러리를 검색 및 로드하면

            - LD_LIBRARY_PATH를 변경하여 libc.so와 같은 공유 라이브러리를 수정 가능 -> 프로그램 파일 소유자 권한으로 임의의 코드 실행 가능 

### DT_RUNPATH

- 배포할 애플리케이션이 실행 바이너리와 공유 라이브러리로 구성된 경우, 실행 바이너리에서 로드할 공유 라이브러리의 경로를 지정할 수 있으면 편리 

$ORIGIN/../lib에서 $ORIGIN = 동적 링커에 의해 해석되는 특수 문자열 

- 동적 링커는 $ORIGIN을 main_runpath_app이 포함된 디렉터리로 확장함
