좋은 질문이다 👍
많은 사람들이 처음에 **“왜 이렇게 복잡하게 만들어놨지?”**라고 느껴.

결론부터 말하면:

> 🔥 `qsort`는 **모든 타입을 정렬할 수 있게 만들었기 때문에** 저렇게 복잡하다.

---

# 1️⃣ C는 “제네릭(generic)”이 없다

C에는 이런 게 없다:

```cpp
sort<int>(arr);     // C++ 가능
sort<string>(arr);  // C++ 가능
```

C는 템플릿이 없음.
그래서 **어떤 타입이 들어올지 모르는데도 정렬해야 함.**

---

# 2️⃣ 그래서 등장한 게 `void*`

```c
void qsort(
    void *base,
    size_t nmemb,
    size_t size,
    int (*compar)(const void *, const void *)
);
```

각 매개변수 의미를 아주 쉽게 설명해볼게.

---

# 🔎 base (void *base)

배열 시작 주소.

왜 `void*`?

→ int 배열일 수도 있고
→ double 배열일 수도 있고
→ 구조체 배열일 수도 있으니까.

---

# 🔎 nmemb (원소 개수)

몇 개 정렬할지.

---

# 🔎 size (원소 하나 크기)

이게 핵심이다.

C는 타입 정보를 모르기 때문에

> "한 칸 건너뛸 때 몇 바이트인지"를 직접 알려줘야 한다.

예:

```
int 배열 → sizeof(int) = 4
double 배열 → sizeof(double) = 8
struct → sizeof(struct) = ?
```

---

# 🔎 비교 함수 (가장 복잡해 보이는 부분)

```c
int (*compar)(const void *, const void *)
```

이건 이렇게 읽으면 된다:

> "void* 두 개를 받아서 int를 반환하는 함수 포인터"

왜 이렇게 하냐?

정렬은 비교가 핵심이기 때문.

---

# 3️⃣ qsort는 내부적으로 이렇게 생각한다

의사코드로 표현하면:

```
for (i)
  for (j)
    if (compar(a, b) > 0)
        swap(a, b)
```

근데 qsort는 **a와 b의 타입을 모른다.**

그래서:

```
compar(const void* a, const void* b)
```

로 받아서

사용자가 직접 캐스팅해서 비교하게 만든 것.

---

# 4️⃣ C++과 비교하면 이해 쉬움

C++:

```cpp
sort(arr.begin(), arr.end());
```

→ 템플릿이 있어서 타입 자동 추론

C:

→ 타입을 모르니까
→ 주소만 받고
→ 크기도 받고
→ 비교 함수도 받는다

---

# 5️⃣ 복잡해 보이지만 사실 4가지뿐

| 매개변수   | 역할     |
| ------ | ------ |
| base   | 배열 시작  |
| nmemb  | 개수     |
| size   | 한 칸 크기 |
| compar | 비교 방법  |

---

# 🔥 왜 이렇게 설계했을까?

C의 철학:

> "유연하고, 타입에 독립적으로 만들자."

그래서 qsort 하나로:

* int 배열
* double 배열
* 문자열 배열
* 구조체 배열

모두 정렬 가능.

---

# 6️⃣ 단점

* 캐스팅 필요
* 타입 안전성 낮음
* 비교 함수 실수하기 쉬움

그래서 C++은 템플릿 sort를 만든 것.

---

# 🎯 정리

qsort가 복잡한 이유는:

> C가 제네릭이 없어서
> 모든 타입을 처리하기 위해
> void* + size + 비교함수 방식을 사용했기 때문.
