이 코드는 (프로그래머스 “모음사전”류처럼) **A/E/I/O/U로 만들 수 있는 길이 1~5 단어를 사전순으로 나열했을 때**, 주어진 `word`가 **몇 번째인지(인덱스)** 찾는 방식이야.
다만 지금 구현은 **치명적인 버그(UB) + 대규모 메모리 누수**가 있고, 반환값도 보통 문제 요구(1부터 시작)와 다를 가능성이 커.

---

## 1) 지금 코드의 핵심 문제들

### ❌ (1) `create_words(0, "")`에서 `strcpy(new_str, str)`가 UB

`str`로 `""`(문자열 리터럴)를 넘겼는데 `new_str`의 크기는 `lev+2`.

* lev=0이면 `new_str` 크기 = 2 (OK)
* 그런데 더 깊은 재귀에서도 `lev`는 “현재 깊이”일 뿐, `str` 길이와 항상 일치하긴 하지만,
* 더 큰 문제는 **초기 `str`이 리터럴이라서 안전성/가독성이 나쁨** + `strcat` 기반 조합은 오류 내기 쉬움.

또한 지금 방식은 매번 `strcpy + strcat`를 해서 비용이 큼.

### ❌ (2) `words[0]`에 `""`가 들어감 (빈 문자열 포함)

```c
words[words_idx++] = str;
```

lev=0인 첫 호출에서 `""`을 words에 넣어버려서,

* 단어 목록이 “빈 문자열부터 시작”
* 보통 모음사전 문제는 빈 문자열을 단어로 보지 않음
  → 인덱스가 1씩 밀릴 가능성 큼.

### ❌ (3) `malloc`한 모든 `new_str`를 free 안 함 → 누수

`3906`개 가까이 문자열을 할당하고 절대 해제하지 않음. 테스트 여러 번 돌리면 누수 심각.

### ❌ (4) `words` 전역에 포인터 저장 + 매 호출마다 초기화 미흡

`words_idx=0`만 초기화하고 기존 포인터 배열은 그대로 남아있어도, 다행히 idx만 쓰긴 하지만 메모리 누수는 계속.

## 2) 이 문제는 “생성” 없이 O(길이)로 바로 풀 수 있음 (정석)

모음 순서가 A,E,I,O,U이고 길이 최대 5일 때, 각 자리의 가중치가 고정이야:

자리별 가중치(앞자리부터):

* 1번째: 781
* 2번째: 156
* 3번째: 31
* 4번째: 6
* 5번째: 1

그리고 답은 보통 **1부터 시작**해서:
각 글자의 인덱스(A=0,E=1,I=2,O=3,U=4)를 `idx`라 하면

> answer += idx * weight[pos] + 1

---

### ✅ 빠르고 메모리 안전한 풀이 (1부터 시작하는 버전)

```c
#include <string.h>

int solution(const char* word) {
    int weights[5] = {781, 156, 31, 6, 1};
    int answer = 0;

    for (int i = 0; word[i] != '\0'; i++) {
        int idx = 0;
        switch (word[i]) {
            case 'A': idx = 0; break;
            case 'E': idx = 1; break;
            case 'I': idx = 2; break;
            case 'O': idx = 3; break;
            case 'U': idx = 4; break;
        }
        answer += idx * weights[i] + 1;
    }
    return answer;
}
```

---

## 3) 주어진 테스트의 정답 (이 정석 기준)

### `word1 = "AAAAE"`

* A(0): 0*781 +1 = 1
* A(0): 0*156 +1 = 1  → 누적 2
* A(0): 0*31  +1 = 1  → 3
* A(0): 0*6   +1 = 1  → 4
* E(1): 1*1   +1 = 2  → **6**

✅ 결과: **6**

### `word2 = "AAAE"`

* A: +1 → 1
* A: +1 → 2
* A: +1 → 3
* E(1) at pos3(weight=6): 1*6 + 1 = 7 → **10**

✅ 결과: **10**

즉 (일반적으로 알려진 “모음사전” 기준) 출력은:

* "AAAAE" → 6
* "AAAE" → 10
