맞아. 이건 “형 변환”이라기보다 **문자(ASCII 코드) 값의 차이를 이용해서 인덱스로 매핑**하는 방식이야. C에서 `char`는 사실상 **작은 정수 타입**처럼 계산에 참여하거든.

---

## 1) 핵심 원리: 문자는 숫자(코드값)다

C에서 `'A'`, `'B'`, `'1'` 같은 문자는 내부적으로 정수 코드값(ASCII)을 가진다.

대표값(ASCII):

* `'A'` = 65
* `'B'` = 66
* ...
* `'H'` = 72
* `'1'` = 49
* `'2'` = 50
* ...
* `'8'` = 56

그래서 문자끼리 빼면 **코드값의 차이(정수)**가 나온다.

---

## 2) `r = pos[0] - 'A'` 가 의미하는 것

`pos`가 `"A1"` 같은 문자열이라고 하면:

* `pos[0]` = `'A'` (열/파일 문자)
* `pos[1]` = `'1'` (행/랭크 문자)

예: `pos[0] = 'C'`

```c
r = 'C' - 'A';
```

코드값으로 보면:

* `'C'` = 67
* `'A'` = 65
* 차이 = 2

즉,

* `'A' - 'A'` = 0
* `'B' - 'A'` = 1
* `'C' - 'A'` = 2
* ...
* `'H' - 'A'` = 7

✅ 결과적으로 **A~H를 0~7로 바로 바꿔주는 매핑**이 됨.

---

## 3) `c = pos[1] - '1'` 도 같은 원리

예: `pos[1] = '6'`

```c
c = '6' - '1';
```

* `'6'` = 54
* `'1'` = 49
* 차이 = 5

즉,

* `'1' - '1'` = 0
* `'2' - '1'` = 1
* ...
* `'8' - '1'` = 7

✅ “체스판 숫자 1~8”을 “인덱스 0~7”로 바꾼다.

---

## 4) 왜 이게 “형 변환”처럼 보일까?

C에서는 산술 연산을 할 때 보통 **정수 승격(integer promotion)**이 일어나.

* `char`끼리 빼기 연산을 하면, 내부적으로 `int`로 올려서 계산함.
* 그래서 결과가 `int`로 나온다.

즉, 코드상으로는:

```c
int r = (int)pos[0] - (int)'A';
```

처럼 동작한다고 생각하면 돼. (명시 캐스팅은 보통 필요 없음)

---

## 5) 전제 조건(중요)

이 방식이 안전하려면 입력이 보장돼야 해:

* `pos[0]`은 `'A'`~`'H'` 범위
* `pos[1]`은 `'1'`~`'8'` 범위

그 외가 들어오면 이상한 값이 나옴:

* `pos[0]='a'`면 `'a'-'A'`는 32 → 아예 범위 밖
* `pos[1]='0'`이면 `'0'-'1'` = -1

그래서 안전하게 하려면 보통 범위 체크를 붙임:

```c
if (pos[0] < 'A' || pos[0] > 'H') return 0;
if (pos[1] < '1' || pos[1] > '8') return 0;
```

(문제에서 입력이 항상 정상이라면 생략 가능)

---

## 6) 이 방식이 `strchr`/배열 탐색보다 좋은 점

* **O(1)**: 탐색이 없음
* 코드가 짧고 빠름
* 버그(널 종료, UB) 위험이 줄어듦

---

원하면, `"A1"`을 (row, col)로 둘지 (col, row)로 둘지 헷갈릴 때 안 헷갈리게 하는 **좌표계 정리 팁**도 같이 정리해줄게.
