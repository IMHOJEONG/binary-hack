좋아. **대각선 합만 필요**면 지금 코드는 “정답은 맞지만” 비용이 너무 커. 개선 포인트를 더 추가해서, 실전 최적 방향을 정리할게.

## 지금 코드의 추가 개선 포인트

1. **행렬 생성 자체가 낭비**

* `matrix[n][n]` 만들고 `-1`로 초기화(O(n²)) 하고
* 달팽이로 전부 채우는 것도 O(n²)
* 그런데 필요한 건 `matrix[i][i]` n개뿐 → 정보의 99%를 버리는 셈

2. **VLA(가변 길이 배열) 위험**

* `int matrix[n][n]`는 스택에 올라가서 n 크면 바로 터질 수 있음
* (특히 프로그래머스 같은 환경에서 스택 제한 빡빡한 경우 있음)

3. **불필요한 방문 체크**

* `matrix[...] != -1` 같은 체크는 “전체 채우기”에서는 필수지만
* 대각선만 구하면 이런 체크가 아예 필요 없음

4. **오버플로우 가능성**

* `answer`가 `int`면 n이 조금만 커도 합이 `int` 범위 넘어갈 수 있음
* 대각선 합은 대략 O(n³) 규모로 커질 수 있어서 `long long`이 안전

# ✅ 최적 해법: O(n)로 대각선 값만 계산하기 (행렬 X)

달팽이(시계방향, 시작 (0,0)=1, 오른쪽 진행)에서
좌표 `(i,i)`의 값만 구해서 더하면 돼.

핵심 관찰:

* 각 칸은 어떤 “레이어(layer)”에 속함
* `(i,i)`는 위쪽/오른쪽/아래/왼쪽 중 어디에 놓이는지 간단히 결정 가능
* 레이어의 시작값(`base`)과 한 변 길이(`len`)만 알면 해당 위치 값이 바로 계산됨

## 구현 (C, O(n), O(1) 메모리)

```c
long long solution(int n) {
    long long ans = 0;

    for (int i = 0; i < n; i++) {
        int layer = i < (n - 1 - i) ? i : (n - 1 - i); // min(i, n-1-i)
        int len = n - 2 * layer;                       // current layer side length

        // base value at (layer, layer): start number of this layer
        // base = 1 + sum_{k=0..layer-1} (perimeter count of layer k)
        // perimeter count for side length L: 4*(L-1)
        // => base = 1 + 4 * sum_{t=0..layer-1} ( (n - 2*t) - 1 )
        // => base = 1 + 4 * ( layer*(n-1) - layer*(layer-1) )
        long long base = 1LL + 4LL * (1LL*layer*(n - 1) - 1LL*layer*(layer - 1));

        // coordinate is (i,i). In this layer, its offset depends on which edge it's on.
        // For diagonal inside a layer:
        // - If i == layer: it's on top edge
        // - Else if i == n-1-layer: it's on bottom edge (and also right edge corner)
        // - Else: it's on right edge
        long long offset;
        if (i == layer) {
            // top edge: (layer, col), col = i
            offset = (i - layer);
        } else if (i == n - 1 - layer) {
            // bottom edge: (row, n-1-layer), row = i, but diagonal means row==col==n-1-layer
            // This is the bottom-right corner of the layer:
            // top (len-1) + right (len-1)
            offset = 2LL * (len - 1);
        } else {
            // right edge: (row, n-1-layer), row = i
            // offset = top edge (len-1) + (row - layer)
            offset = (len - 1) + (i - layer);
        }

        ans += base + offset;
    }

    return ans;
}
```

### 체크 예시

* n=1 → [1], 대각선=1
* n=2 → [[1,2],[4,3]] 대각선=1+3=4
* n=3 → [[1,2,3],[8,9,4],[7,6,5]] 대각선=1+9+5=15

(이 구현은 그 패턴 기준)

# ✅ 더 줄일 수 있는 개선 (선택)

* 위 코드는 `i`마다 레이어 계산/분기하는 방식이라 O(n)인데,
  더 “수식 위주”로도 가능해. 다만 가독성이 떨어져서 코테에서는 위가 밸런스 좋음.

# 🎯 최종 권장 사항

* “대각선 합만”이면 **행렬을 만들지 말 것**
* `answer`는 **long long**
* 패턴이 확실한 달팽이는 **레이어 기반 O(n) 계산**이 가장 깔끔

원래 네 코드가 “오른쪽→아래→왼쪽→위” 시계방향, 시작 (0,0)=1 맞지?
맞다면 위 O(n) 풀이가 그대로 정답이야.
만약 시작 방향/시작 위치가 다른 달팽이면 그 규칙에 맞춰 offset만 바꾸면 돼.
