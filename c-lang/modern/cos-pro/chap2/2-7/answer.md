이 코드는 👉 **거스름돈을 가장 적은 동전 개수로 만드는 문제 (그리디)** 입니다.

---

## ✅ 코드 동작 원리

```c
int coin[8] = {10, 50, 100, 500, 1000, 5000, 10000, 50000};
```

* 큰 단위부터 사용하기 위해 `idx = 7` (50000원)부터 시작
* 가능한 만큼 나누고
* 남은 돈으로 계속 반복

---

## 🔍 예시

### money = 87650

1. 50000 → 1개 (남은 37650)
2. 10000 → 3개 (남은 7650)
3. 5000 → 1개 (남은 2650)
4. 1000 → 2개 (남은 650)
5. 500 → 1개 (남은 150)
6. 100 → 1개 (남은 50)
7. 50 → 1개 (남은 0)

👉 총 개수 = **10개**

---

# ⚠️ 하지만 이 코드의 문제점

```c
while (money > 0){
    ...
    idx -= 1;
}
```

💥 **idx가 음수가 될 위험이 있음**

만약:

* money가 10의 배수가 아닐 경우
* 혹은 coin 배열이 변경될 경우

👉 배열 범위 초과 가능

---

# ✅ 안전한 버전

```c
int solution(int money) {
    int coin[8] = {50000, 10000, 5000, 1000, 500, 100, 50, 10};
    int counter = 0;

    for (int i = 0; i < 8; i++) {
        counter += money / coin[i];
        money %= coin[i];
    }

    return counter;
}
```

✔ 더 안전
✔ idx 관리 불필요
✔ 읽기 쉬움

---

# 🧠 왜 이게 가능한가?

한국 화폐 단위는 **정규 화폐 시스템 (canonical coin system)** 이라서

> 큰 단위부터 greedy로 선택해도 항상 최소 개수 보장됨

하지만 모든 동전 시스템에서 이게 성립하는 건 아님.

예:

```
coin = {1, 3, 4}
money = 6
```

greedy:
4 + 1 + 1 = 3개 ❌
정답:
3 + 3 = 2개 ✔
