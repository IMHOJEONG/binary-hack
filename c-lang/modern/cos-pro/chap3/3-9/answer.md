이 코드는 **길이 k짜리 연속 구간(subarray)의 합 중 최댓값**을 구하는 전형적인 *슬라이딩 윈도우*야. 동작도 정상이고, `main()`의 두 테스트 케이스 결과는 아래처럼 나와.

---

## 1) 첫 번째 테스트

`revenue1 = {1, 1, 9, 3, 7, 6, 5, 10}`, `k = 4`

길이 4 구간 합:

* 1+1+9+3 = 14
* 1+9+3+7 = 20
* 9+3+7+6 = 25  ✅ 최대
* 3+7+6+5 = 21
* 7+6+5+10 = 28? 잠깐 계산: 7+6=13, +5=18, +10=28 ✅ 이게 최대

따라서 반환값은 **28**

---

## 2) 두 번째 테스트

`revenue2 = {1, 1, 5, 1, 1}`, `k = 1`

길이 1 구간 합은 각 원소 그대로:

* 1, 1, 5, 1, 1 → 최대는 **5**

---

## ✅ 그래서 출력은

```
solution 함수의 반환 값은 28 입니다.
solution 함수의 반환 값은 5 입니다.
```

## 참고로 안전성 체크(옵션)

현재 코드는 `k > revenue_len`이면 초기 합 구간에서 배열 범위 초과가 날 수 있어. 보통은:

```c
if (k <= 0 || k > revenue_len) return 0; // 또는 에러 처리
```

원하면 “최댓값뿐 아니라 그 구간의 시작 인덱스/구간 자체”까지 같이 반환하는 버전도 만들어줄까?

----

슬라이딩 윈도우는 **“연속된 구간(윈도우) 길이가 고정(k)”**일 때, 구간 합/평균/최댓값 등을 **매번 처음부터 다시 계산하지 않고** 한 칸씩 “밀면서” 빠르게 갱신하는 기법이야.

네 코드가 딱 “길이 k인 연속 구간의 합 중 최댓값” 문제를 푸는 전형적인 형태고, 아래에서 코드 흐름을 그대로 따라가며 설명할게.

---

## 핵심 아이디어

길이 `k` 구간의 합을 매번 새로 계산하면:

* 구간 하나 합 계산: O(k)
* 구간 개수: 약 (n - k + 1)
* 총: O((n-k+1) * k) ≈ O(nk)

슬라이딩 윈도우는 합을 이렇게 갱신해:

> 다음 구간 합 = 이전 구간 합
> − (빠지는 값 1개)
> + (새로 들어오는 값 1개)

그래서 매 칸 이동이 O(1), 전체가 O(n)이 됨.

---

## 네 코드 라인별 설명

```c
int solution(int revenue[], int revenue_len, int k) {
    int answer = 0;
    int sum = 0;
```

* `sum`: 현재 윈도우(길이 k)의 합
* `answer`: 지금까지 본 윈도우 합의 최댓값

---

### 1) 첫 윈도우 합을 먼저 만든다

```c
    for (int i = 0; i < k; i++) {
        sum += revenue[i];
    }
    answer = sum;
```

여기서 `sum`은 첫 구간:

* `revenue[0] ~ revenue[k-1]` 합

그리고 `answer`를 그 값으로 초기화함.
(왜냐면 아직 비교 대상이 없으니까 “첫 값”이 임시 최대값)

---

### 2) 윈도우를 한 칸씩 오른쪽으로 밀면서 갱신

```c
    for (int i = k; i < revenue_len; i++) {
        sum = sum - revenue[i - k] + revenue[i];
        if (answer < sum)
            answer = sum;
    }
```

이 루프에서 `i`는 “새로 윈도우에 들어오는 원소의 인덱스”야.

* 새로 들어오는 값: `revenue[i]`
* 윈도우에서 빠지는 값: `revenue[i-k]`

왜 `i-k`가 빠지냐면,
현재 윈도우가 길이 k라서, 한 칸 오른쪽으로 가면 맨 왼쪽 값이 하나 밀려나감.

#### 갱신식

```c
sum = sum - revenue[i - k] + revenue[i];
```

* `- revenue[i-k]` : 이전 윈도우의 맨 왼쪽 값 제거
* `+ revenue[i]` : 새로 들어온 오른쪽 값 추가

갱신한 `sum`이 더 크면 `answer` 업데이트.

---

### 3) 최댓값 반환

```c
    return answer;
}
```

## 예제로 한 번 “손으로” 따라가기 (revenue1)

`revenue1 = {1, 1, 9, 3, 7, 6, 5, 10}`, `k=4`

### 초기 윈도우 (0~3)

* sum = 1+1+9+3 = 14
* answer = 14

이제 i는 4부터 시작 (새로 들어올 인덱스)

### i=4 (윈도우 1~4)

* 빠짐: revenue[0] = 1
* 들어옴: revenue[4] = 7
* sum = 14 - 1 + 7 = 20
* answer = 20

### i=5 (윈도우 2~5)

* 빠짐: revenue[1] = 1
* 들어옴: revenue[5] = 6
* sum = 20 - 1 + 6 = 25
* answer = 25

### i=6 (윈도우 3~6)

* 빠짐: revenue[2] = 9
* 들어옴: revenue[6] = 5
* sum = 25 - 9 + 5 = 21
* answer = 25 유지

### i=7 (윈도우 4~7)

* 빠짐: revenue[3] = 3
* 들어옴: revenue[7] = 10
* sum = 21 - 3 + 10 = 28
* answer = 28

최종 반환 28.

## 왜 빠른가?

매 이동마다 딱 2번만 연산함:

* 하나 빼고
* 하나 더하고

그래서 **O(n)**.

---

## 흔한 실수/주의점

### 1) k가 잘못된 입력이면 터짐

`k > revenue_len`이면 첫 합 계산에서 배열 범위 초과.

보통 이렇게 방어:

```c
if (k <= 0 || k > revenue_len) return 0; // 정책에 맞게
```

### 2) 음수 값이 포함될 수 있으면 answer 초기값 주의

지금은 `answer=sum`으로 시작해서 안전.
(만약 `answer=0`만 하고 시작했다면 전부 음수일 때 틀림)

### 3) 합이 int 범위를 넘을 수 있으면 long long

매출이 큰 값이면:

```c
long long sum = 0, answer = 0;
```

## 확장: “최댓값 구간의 시작 인덱스도” 구하고 싶으면?

`answer` 갱신될 때 시작 인덱스는 `i-k+1`이야.

원하면 그 버전도 같이 만들어줄게.
