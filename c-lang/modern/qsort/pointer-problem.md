좋아. 전체적으로 감이 거의 맞았고, **몇 군데 “포인터 한 단계”랑 “배열/포인터의 타입 규칙”**에서 딱 흔히 하는 실수가 섞여 있어. 항목별로 “정답 타입 + 왜 그런지 + 네 답에서 뭐가 달랐는지”로 설명할게.

---

## Q1

```c
int x = 10;
int *p = &x;
```

1. `x` → **int** ✅

* 변수 자체는 int.

2. `p` → **int*** ✅

* `p`는 `x`의 주소를 담는 포인터.

3. `&x` → **int*** ✅

* `x`의 주소이므로 `int*`.

4. `*p` → **int** ✅

* `p`가 가리키는 대상이 `int`니까 역참조하면 `int`.

5. `&p` → **int**** ❌ (너: int*)

* `p`의 타입이 `int*`니까, 그 **주소**는 `int**`가 됨.

  * 규칙: `T* 변수`의 주소는 `T**`

✅ 정리: Q1에서 틀린 건 `&p` 하나. `int**`가 맞아.

---

## Q2

```c
char *s = "Java";
char **pp = &s;
```

1. `s` → **char*** ✅

* 문자열 시작 주소를 담는 포인터.

2. `pp` → **char**** ✅

* `s`의 주소를 담는 포인터.

3. `*pp` → **char*** ✅

* `pp`가 가리키는 건 `s`(char*)이므로, 한 번 역참조하면 char*.

4. `**pp` → **char** ✅ (너: char)

* `*pp`가 `char*`이고, 그걸 한 번 더 역참조하면 “문자 하나” `char`가 맞아. ✅
  (여긴 네 답도 맞음)

5. `&s` → **char**** ✅ (너: char**)

* `s`가 `char*`이니까 주소는 `char**`.

6. `&pp` → **char***** ✅

* `pp`가 `char**`이니까 주소는 `char***`.

✅ Q2는 전부 정확.

---

## Q3 (여기서 배열 규칙이 핵심)

```c
char *arr[] = {"A", "B", "C"};
```

### 먼저 선언 자체

* `arr`는 “`char*` 3개짜리 배열”
  즉 **array of 3 pointers-to-char**

1. `arr` → **char* [3]** (표기상: `char*[]`도 OK) ✅

* “배열 타입”으로 말하면 `char* [3]`.

⚠️ 단, **식(expression)에서 `arr`는 대부분 `&arr[0]`로 decay** 해서 `char**`처럼 쓰이는 경우가 많아.
하지만 “타입이 뭐냐” 질문이면 원칙적으로는 배열 타입.

2. `arr[0]` → **char*** ✅

* `"A"`의 시작 주소.

3. `&arr[0]` → **char**** ✅

* `arr[0]`가 `char*`이므로 주소는 `char**`.

4. `*(arr)` → **char*** ❌ (너: char[])

* `arr`는 식에서 보통 `&arr[0]`로 decay → 타입이 `char**`처럼 동작
* `*(arr)`는 `arr[0]`와 동일
* `arr[0]` 타입은 `char*`
  ➡️ 그래서 `*(arr)`도 **char***.

5. `*(arr + 1)` → **char*** ❌ (너: char[])

* `arr + 1`은 `&arr[1]`
* 역참조하면 `arr[1]`
* `arr[1]`은 `char*`
  ➡️ 그래서 **char***.

보너스 6) `&arr` → **char* (*)[3]** ❌ (너: char**[])

* 이게 제일 중요한 포인트.
* `arr`는 “배열”이고, `&arr`는 “배열 전체의 주소”야.
* 그래서 타입은 **pointer to array of 3 char***
  즉: `char* (*)[3]`

🔍 차이 직감용:

* `arr` (식에서) ≈ `&arr[0]`  (첫 원소 주소)
* `&arr` = “배열 덩어리 전체의 주소” (한 단계 다른 포인터)

## Q4

```c
int arr[] = {3, 1, 2};

int cmp(const void* a, const void* b) {
}
```

1. `arr`의 타입 → **int[3]** ✅ (너: int[])

* 정확히 쓰면 길이 포함 `int[3]`.

2. `arr[0]` → **int** ✅

3. `&arr[0]` → **int*** ✅

4. comparator 안에서 `a`의 “실제 타입” → **int*** ✅(의미상), 하지만 표기는 주의

* 선언상 `a`는 `const void*`가 맞고(너가 쓴 답) ✅
* 하지만 “qsort가 넘기는 실제 값”은 **원소의 주소**라서, 여기서는 `&arr[i]` → **int*** 가 실제 의미.

5. `*(int*)a` → **int** ✅

✅ Q4는 4번만 “선언 타입 vs 실제 의미 타입”을 구분해두면 완벽.

---

## Q5

```c
char *arr[] = {"Java", "C++"};

int cmp(const void* a, const void* b) {
    return strcmp(*(char**)a, *(char**)b);
}
```

1. `a`의 실제 타입 → 선언상 **const void*** ✅

* 실제 의미상은 `&arr[i]`라서 **char****.

2. `(char**)a`의 타입 → **char**** ✅

* 캐스팅 결과 그대로.

3. `*(char**)a`의 타입 → **char*** ✅

* `char**`를 한 번 역참조하면 `char*`.

4. 왜 `*(char*)a`는 틀린가? (네 답: “문자열 안 문자열 값이라서”) → 방향은 맞는데 더 정확히

* `a`가 가리키는 건 **“char* 원소(arr[i])가 저장된 메모리 위치”**야.
* 즉 메모리에는 “문자열 주소(포인터 값)”이 들어있음.
* 그런데 `*(char*)a`는 그 메모리를 **문자(char)들의 메모리라고 착각**하고 첫 바이트만 읽어버림.
* 결과적으로 `strcmp`에 들어갈 `char*`(문자열 주소)가 아니라,
  “포인터 값의 첫 바이트” 같은 쓰레기 값을 다루게 되어 UB(정의되지 않은 동작)로 이어짐.

한 줄로:

* `a`는 `char**`로 해석해야 맞고,
* `char*`로 해석하면 **포인터 값을 문자 배열로 오해**하게 된다.

5. `char ***triple = &pp;` 라면 `***triple`의 타입?

* 여기서 `pp`가 **char**** 라고 했으니,

  * `&pp`는 **char*****
  * `triple`은 **char*****
  * `*triple` → **char****
  * `**triple` → **char***
  * `***triple` → **char** ✅ (너: char*)
    즉 최종은 “문자 하나”.

# 너가 틀린 것만 빠르게 체크리스트

* Q1-5: `&p`는 `int**`
* Q3-4,5: `*(arr)` / `*(arr+1)`는 `char*`
* Q3-6: `&arr`는 `char* (*)[3]`
* Q5-5: `***triple`은 `char`
