좋은 질문 👍
C에서 `.` 와 `->` 차이는 **"그 변수가 포인터냐 아니냐"** 차이야.

---

# 🔥 핵심 한 줄 요약

| 상황          | 사용   |
| ----------- | ---- |
| 구조체 변수      | `.`  |
| 구조체 **포인터** | `->` |

---

# ✅ 1️⃣ `.` 을 쓰는 경우

```c
Pair p;
p.count = 3;   // OK
```

여기서 `p`는 **구조체 그 자체**야.
그래서 그냥 `.` 으로 접근.

---

# ✅ 2️⃣ `->` 를 쓰는 경우

```c
Pair *pp = &p;
pp->count = 3;  // OK
```

`pp`는 **구조체의 주소(포인터)**
그래서 `->` 사용.

---

# 🔎 네 코드에서 왜 `->` ?

```c
int cmp_pair_count_desc(const void *a, const void *b) {
    const Pair *pa = (const Pair *)a;
    const Pair *pb = (const Pair *)b;
```

여기서

```c
pa
```

는 `Pair *` 타입이야.
즉 **구조체 포인터**.

그래서

```c
pa->count
```

를 쓰는 것.

---

# 🔬 만약 `.` 쓰려면?

이렇게 써야 함:

```c
(*pa).count
```

왜냐하면:

```
pa->count
= (*pa).count
```

즉,

```
-> 는 (*포인터).멤버 의 축약 문법
```

---

# 🎯 예시로 완전 이해

### 구조체 변수

```c
Pair p;
p.count = 10;  // .
```

### 구조체 포인터

```c
Pair *pp = &p;
pp->count = 10;        // ->
(*pp).count = 10;      // 동일한 표현
```

---

# ⚠️ 왜 qsort comparator에서는 항상 `->`가 많을까?

`qsort`는 항상 **주소(void*)**를 넘겨줘.

```c
int cmp(const void *a, const void *b)
```

`a`, `b`는 포인터니까
캐스팅하면 결국 **포인터 타입**이 돼.

그래서 멤버 접근은 `->`가 되는 것.

---

# 💡 한 번에 정리

```
구조체 자체      →  .
구조체 포인터    →  ->
```
