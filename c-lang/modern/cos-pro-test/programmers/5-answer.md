문제 조건(한 번 접기)에서 “겹칠 수 있는 두 칸”은 **항상 같은 행끼리(가로 접기 X, 세로 접기 O)** 또는 **같은 열끼리(가로 접기 O, 세로 접기 X)**로만 생겨요.

* **세로로 접기(좌/우 접기)** → 같은 **행 i**에서 열 쌍이 겹침
  가능한 열 쌍: (0,1), (1,2), (2,3), (0,3)
* **가로로 접기(상/하 접기)** → 같은 **열 i**에서 행 쌍이 겹침
  가능한 행 쌍도 똑같이: (0,1), (1,2), (2,3), (0,3)

너의 코드는 첫 항 `grid[i][j] + grid[i][k]`로 “같은 행” 케이스는 잘 보는데,
두 번째 항을

```c
grid[i][j] + grid[abs(k-i-j)][j]
```

처럼 “이상한 행 인덱스 계산”으로 만들면서, **가로 접기에서 필요한 (행 쌍) × (모든 열)** 조합을 전부 커버하지 못해요. (특정 열에서는 (0,3) 같은 쌍이 아예 계산되지 않는 식)

---

## ✅ 한 줄만 바꾸면 되는 정답 수정

가로 접기는 “같은 열에서 행 쌍(j,k)”을 보면 되니까, 두 번째 후보를 **전치(Transpose) 관점**으로 이렇게 계산하면 됩니다:

* 세로 접기 후보: `grid[i][j] + grid[i][k]`  (행 i 고정, 열 쌍 j,k)
* 가로 접기 후보: `grid[j][i] + grid[k][i]`  (열 i 고정, 행 쌍 j,k)

즉, 아래 한 줄만 바꾸면 끝.

### 🔧 수정 전

```c
answer = max(answer, max(grid[i][j] + grid[i][k], grid[i][j] + grid[abs(k-i-j)][j]));
```

### ✅ 수정 후 (한 줄 변경)

```c
answer = max(answer, max(grid[i][j] + grid[i][k], grid[j][i] + grid[k][i]));
```

---

## 왜 이게 “모든 접기”를 다 커버하냐?

현재 루프가 만드는 (j,k) 쌍은 정확히 접을 때 가능한 쌍만 생성해요:

* j=0 → k=1,3  → (0,1), (0,3)
* j=1 → k=2    → (1,2)
* j=2 → k=3    → (2,3)

이 쌍을

* 같은 행(i)에서 쓰면 **세로 접기**
* 같은 열(i)에서 쓰면 **가로 접기**

가 되어, “한 번 접어서 생기는 모든 겹침 쌍”을 정확히 다 보게 됩니다.

원하면, 내가 위 수정을 적용한 전체 `solution()` 함수 버전도 깔끔하게 붙여줄게.

# 🎯 4×4 격자 좌표 먼저 정리

좌표는 이렇게 본다:

```
(row, col)

(0,0) (0,1) (0,2) (0,3)
(1,0) (1,1) (1,2) (1,3)
(2,0) (2,1) (2,2) (2,3)
(3,0) (3,1) (3,2) (3,3)
```

즉:

```
grid[row][col]
```

---

# 🔥 1️⃣ 세로로 접는 경우 (좌우 접기)

세로선 기준 접기 → **같은 행(row)** 에서 열(col)만 바뀐다.

예: 가운데 세로선 기준

```
( i , 0 )  ↔  ( i , 3 )
( i , 1 )  ↔  ( i , 2 )
```

즉

```
grid[i][j] + grid[i][k]
```

여기서

* i = 행 고정
* j,k = 열 쌍

👉 그래서 코드가

```c
grid[i][j] + grid[i][k]
```

인 게 맞다.

---

# 🔥 그림으로 보기 (세로 접기)

예를 들어 i = 2행

```
(2,0) (2,1) (2,2) (2,3)

6      13     36     14
```

세로로 접으면

```
(2,0) ↔ (2,3)
(2,1) ↔ (2,2)
```

행은 그대로고 열만 바뀐다.

---

# 🔥 2️⃣ 가로로 접는 경우 (상하 접기)

가로선 기준 접기 → **같은 열(col)** 에서 행(row)이 바뀐다.

예: 가운데 가로선 기준

```
(0, i) ↔ (3, i)
(1, i) ↔ (2, i)
```

즉

```
grid[j][i] + grid[k][i]
```

여기서

* i = 열 고정
* j,k = 행 쌍

---

# 🔥 그림으로 보기 (가로 접기)

예를 들어 i = 2열

```
(0,2)
(1,2)
(2,2)
(3,2)

16
15
36
19
```

가로로 접으면

```
(0,2) ↔ (3,2)
(1,2) ↔ (2,2)
```

열은 그대로고 행만 바뀐다.

---

# 🔥 왜 인덱스가 뒤집히는 것처럼 보이냐?

현재 반복문은 이렇게 생겼지:

```c
for (int i = 0; i < 4; i++)
  for (int j = 0; j < 4; j++)
    for (int k = j+1; k < 4; k += 2)
```

여기서:

* i는 "고정 축"
* j,k는 "쌍을 만드는 축"

---

## 세로 접기 해석

* i = 행
* j,k = 열

→ `grid[i][j] + grid[i][k]`

---

## 가로 접기 해석

* i = 열
* j,k = 행

→ `grid[j][i] + grid[k][i]`

---

# 🔥 시각적으로 비교

세로 접기:

```
grid[i][j]
     ↓
행 i 고정
열 j,k 이동
```

가로 접기:

```
grid[j][i]
     ↓
열 i 고정
행 j,k 이동
```

---

# 🔥 한 줄 요약

> 세로 접기 → 행 고정
> 가로 접기 → 열 고정

그래서 인덱스가

```
grid[i][j]
→
grid[j][i]
```

처럼 바뀌는 것처럼 보이는 것.

---

# 🔥 핵심 개념

이건 "행렬 전치(transpose)"랑 같은 개념이야.

가로 접기를 세로 접기처럼 처리하려면
좌표를 바꿔서 생각하면 된다.

# 🔥 직관적으로 기억하는 방법

```
접는 선이 세로면 → 같은 행
접는 선이 가로면 → 같은 열
```
