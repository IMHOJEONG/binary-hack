좋아. 네가 말한 예시(스케줄이 `[6,2,3,5,5]`이고 “기계는 **최대 3일 연속** 처리 가능”, 최소 사람=2)는 **거의 확실히** 이런 류야:

* 각 날짜 `i`에는 해야 할 “작업량” `SCHEDULE[i]`가 있음 (0도 가능)
* 기계는 **연속으로 최대 K일(=3일)**까지 처리 가능
* 사람이 **하루 투입(또는 1회 투입)**되면 그날의 작업을 사람이 처리하면서 **기계 연속 카운트가 리셋**되거나(=그 구간을 끊음), 혹은 “사람이 들어간 날은 기계 연속 처리에 포함되지 않음”
* 목표: 전체를 처리하면서 **사람이 투입되는 횟수(또는 사람 작업량 합)를 최소화**

근데 여기서 중요한 포인트가 하나 있어.
네가 “사람은 최소 2만큼”이라고 한 걸 보면, **사람 비용이 ‘횟수(일수)’가 아니라 ‘작업량(값)’ 합**일 가능성이 커.

즉,

* 기계가 처리한 날들은 비용 0
* 사람이 처리한 날들은 비용 = `SCHEDULE[i]` (그날 작업량)
* 제약: 기계가 처리한 날이 연속으로 K일을 넘으면 안 됨
* 목표: 사람 비용 합 최소

이 모델이면 `[6,2,3,5,5]`, K=3에서

* 사람이 `2`와 `?`만 처리해서 합이 2가 되려면 **사람이 처리한 날이 딱 한 번이고 그 값이 2**여야 함.
* 즉 사람은 “2가 있는 날(두 번째 날)”만 처리하고 나머지는 기계가 처리.

연속 제약을 만족하려면 “기계가 처리한 날들의 연속 길이”가 3 이하가 되어야 하는데,

* 만약 사람이 day2(값 2)만 처리하면, 기계는 day1 + (day3~day5)로 가게 되고

  * day3~day5는 연속 3일 → OK
  * day1은 단독 → OK
    그래서 사람 비용 합 = 2가 가능해져. 딱 네가 말한 결과랑 맞아떨어져.

## 이 문제의 정답 접근: DP (가장 안전)

핵심은 “연속으로 기계가 처리한 날짜 수”가 상태가 되는 전형 DP야.

### 상태 정의

* `dp[i][c]` = `i`번째 날까지 처리했고,
  마지막에 **기계로 연속 처리한 일수 = c** 일 때의 최소 사람 비용

  * `c`는 `0..K` (0은 “마지막 날을 사람이 처리해서 기계 연속이 끊긴 상태”)

### 전이

1. `i`번째 날을 **사람이 처리**

* 비용 + `SCHEDULE[i]`
* 기계 연속 처리 = 0으로 리셋
* `dp[i+1][0] = min(dp[i+1][0], dp[i][c] + SCHEDULE[i])`

2. `i`번째 날을 **기계가 처리**

* 비용 +0
* 단, `c < K`일 때만 가능
* `dp[i+1][c+1] = min(dp[i+1][c+1], dp[i][c])`

### 답

* `min_c dp[n][c]`

시간복잡도 `O(n*K)`라 코테에서 아주 무난.

## C 코드 템플릿 (사람 비용 = 작업량 합 최소 버전)

```c
#include <stdio.h>
#include <limits.h>

#define INF (LLONG_MAX/4)

long long min_ll(long long a, long long b) { return a < b ? a : b; }

long long solve_min_human_cost(const int *a, int n, int K) {
    // dp[c] = 현재 day i까지 처리했을 때, 기계 연속 c 상태의 최소 비용
    long long dp[101];      // K 최대가 크면 동적할당으로 바꾸기
    long long ndp[101];

    for (int c = 0; c <= K; c++) dp[c] = INF;
    dp[0] = 0;

    for (int i = 0; i < n; i++) {
        for (int c = 0; c <= K; c++) ndp[c] = INF;

        for (int c = 0; c <= K; c++) {
            if (dp[c] == INF) continue;

            // 1) 사람이 처리
            ndp[0] = min_ll(ndp[0], dp[c] + a[i]);

            // 2) 기계가 처리 (연속 제한)
            if (c < K) {
                ndp[c + 1] = min_ll(ndp[c + 1], dp[c]);
            }
        }

        for (int c = 0; c <= K; c++) dp[c] = ndp[c];
    }

    long long ans = INF;
    for (int c = 0; c <= K; c++) ans = min_ll(ans, dp[c]);
    return ans;
}

int main() {
    int a[] = {6,2,3,5,5};
    int n = 5;
    int K = 3;
    printf("%lld\n", solve_min_human_cost(a, n, K)); // 2
    return 0;
}
```

## MAX_DATE는 어디에 쓰이냐?

보통은 그냥 `n = MAX_DATE` (배열 길이)로 주어지거나,
날짜가 1..MAX_DATE인데 스케줄이 “일이 있는 날만 sparse하게 주어짐”이면

* 길이 MAX_DATE짜리 배열로 펴서 위 DP 돌리거나,
* 일이 없는 날(0)은 “사람 처리 비용 0”이라 DP에 그대로 넣으면 됨.

## 체크: 이 문제에서 “사람 최소”가 의미하는 게 둘 중 뭐였어?

네 기억대로 “최소 2”가 딱 떨어지는 걸 보면 **사람 비용 = 작업량 합**일 확률이 높지만,
혹시 문제에서 사람이 한 번 투입할 때 그날 작업량이 얼마든 “1회”로 치는 모델이면 답이 달라져.

* 사람 비용 = **투입 횟수 최소** → `[6,2,3,5,5], K=3`이면 보통 1회면 충분(중간 하루 끊기)이라 “2”가 잘 안 나와.

그래서 네가 기억한 “2”는 **작업량 합 최소** 모델이 더 자연스럽게 맞아.

원하면 내가 위 DP를:

* (A) 사람 비용 = 작업량 합 최소
* (B) 사람 비용 = 투입 횟수 최소
* (C) 사람 비용 = “사람은 하루에 처리 가능한 최대량이 있음” (cap)
  이렇게 3가지 버전으로 각각 템플릿 만들어 줄게.
